# Day 6 Deliverable: API Automation with Python and pytest

## Learning objectives

- Send HTTP requests with `requests.Session` and bounded timeouts.
- Reuse a pytest fixture for authentication and test-owned booking data.
- Parameterize boundary inputs and check response status, content type, fields, and data types.
- Exercise negative behavior, CRUD, cleanup, and JUnit XML reporting.

## Where the implementation lives

The existing `api-tests/` path remains the canonical suite so the project's
original test command and report location remain usable:

- [`test_booking_api.py`](../api-tests/test_booking_api.py) contains 15 collected cases, including parameterized booking ID and price values.
- `api_session` provides a `requests.Session`; `auth_token` obtains an API token when a test needs one.
- `booking_factory` creates uniquely identified test data and deletes only its own remaining bookings in fixture teardown.
- The base URL and demo credentials can be overridden with `RESTFUL_BOOKER_BASE_URL`, `RESTFUL_BOOKER_USERNAME`, and `RESTFUL_BOOKER_PASSWORD`.

The public demo API contract has service-specific status behavior: invalid
credentials return a `reason` body with status 200, unauthenticated writes
return 403, invalid PUT data returns 400, and a missing GET returns 404. See
the [route implementation](https://github.com/mwinteringham/restful-booker/blob/master/routes/index.js#L170-L181),
[write and auth handlers](https://github.com/mwinteringham/restful-booker/blob/master/routes/index.js#L422-L448),
[auth handler](https://github.com/mwinteringham/restful-booker/blob/master/routes/index.js#L641-L651),
and [validation rules](https://github.com/mwinteringham/restful-booker/blob/master/helpers/validationrules.js#L1-L10).

The price boundary exercise tries -1, 0, and 1. The demo API validates that
`totalprice` is present but does not document a minimum, so these cases check
numeric handling and round-trip values; they do not assert a business rule that
negative prices must be rejected.

## Run in PowerShell

From the repository root:

```powershell
.\.venv\Scripts\python.exe -m pytest api-tests -v --junitxml=api-tests\report.xml
```

Run a selected group:

```powershell
.\.venv\Scripts\python.exe -m pytest api-tests -k booking_id_boundaries -v
```

`api-tests\report.xml` is generated by the first command and is ignored by
Git. Each HTTP call has a 15-second timeout. The suite does not retry requests.
